## 🔐 Commit-Reveal Logic (UPDATED)

### **Current Issue:**
- **Commit**: Sends `score = 0` → creates hash(0, nonce, address)
- **Reveal**: Sends `score = 0` → verifies hash(0, nonce, address)
- ❌ Problem: Actual score is never verified on-chain!

### **Updated Logic:**

#### **Commit Phase** (Before Game)
```solidity
function commitScore(uint256 placeholderScore, uint256 nonce) external payable nonReentrant {
    // User commits hash BEFORE playing
    // placeholderScore = 0 (not used, just for compatibility)
    // nonce = random number generated by client
    
    bytes32 scoreHash = keccak256(abi.encodePacked(
        placeholderScore,  // Always 0
        nonce,
        msg.sender
    ));
    
    commits[msg.sender][currentPeriod] = Commit({
        scoreHash: scoreHash,
        timestamp: block.timestamp,
        nonce: nonce
    });
}
```

#### **Reveal Phase** (After Game)
```solidity
function revealScore(uint256 actualScore, uint256 nonce) external nonReentrant {
    // User reveals ACTUAL weighted score after playing
    // actualScore = weighted score from game (NOT 0!)
    // nonce = same nonce used in commit
    
    Commit storage c = commits[msg.sender][currentPeriod];
    require(c.scoreHash != bytes32(0), "No commit found");
    
    // IMPORTANT: Calculate hash using actual score, not 0!
    bytes32 providedHash = keccak256(abi.encodePacked(
        actualScore,  // Actual weighted score
        nonce,
        msg.sender
    ));
    
    require(providedHash == c.scoreHash, "Invalid reveal");
    
    // Store the verified score
    scores[msg.sender][currentPeriod] = actualScore;
}
```

### **Key Changes:**
1. ✅ **Commit**: Still uses hash(0, nonce, address) for pre-game commitment
2. ✅ **Reveal**: Uses hash(weightedScore, nonce, address) to verify actual score
3. ✅ **Time**: No time limit between commit and reveal - only nonce validation matters
4. ✅ **Nonce**: Must be the same in both commit and reveal to match

## 📅 Daily Period Calculation (00:00 UTC)

### **Formula:**

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract EtherTrialsPointBasedV4 {
    // Period calculation: Daily periods starting at 00:00 UTC
    
    /**
     * @dev Get current period number
     * @return Current period (days since Unix epoch)
     */
    function getCurrentPeriod() public view returns (uint256) {
        return block.timestamp / 1 days;
        // Alternative: return block.timestamp / 86400;
    }
    
    /**
     * @dev Get period start time (00:00 UTC)
     * @param period Period number
     * @return Unix timestamp of period start
     */
    function getPeriodStartTime(uint256 period) public pure returns (uint256) {
        return period * 1 days;
        // Alternative: return period * 86400;
    }
    
    /**
     * @dev Get period end time (next day 00:00 UTC)
     * @param period Period number
     * @return Unix timestamp of period end
     */
    function getPeriodEndTime(uint256 period) public pure returns (uint256) {
        return (period + 1) * 1 days;
        // Alternative: return (period + 1) * 86400;
    }
    
    /**
     * @dev Check if period is active
     * @param period Period number
     * @return True if period is currently active
     */
    function isPeriodActive(uint256 period) public view returns (bool) {
        uint256 currentPeriod = getCurrentPeriod();
        return period == currentPeriod;
    }
    
    /**
     * @dev Get time remaining in current period (seconds)
     * @return Seconds until next period starts
     */
    function getTimeRemainingInPeriod() public view returns (uint256) {
        uint256 currentPeriod = getCurrentPeriod();
        uint256 periodEnd = getPeriodEndTime(currentPeriod);
        return periodEnd - block.timestamp;
    }
}
```

### **How It Works:**

1. **Period 0**: January 1, 1970 00:00:00 UTC → January 2, 1970 00:00:00 UTC
2. **Period 1**: January 2, 1970 00:00:00 UTC → January 3, 1970 00:00:00 UTC
3. **Period N**: (N days since epoch) 00:00:00 UTC → (N+1 days) 00:00:00 UTC

**Current Date Example (2025):**
- `block.timestamp` = 1,736,899,200 (January 15, 2025 00:00:00 UTC)
- `getCurrentPeriod()` = 1,736,899,200 / 86400 = **20,103**
- Period starts at: 20,103 × 86400 = January 15, 2025 00:00:00 UTC
- Period ends at: 20,104 × 86400 = January 16, 2025 00:00:00 UTC

### **Benefits:**
✅ **Always starts at 00:00 UTC** - Predictable and consistent
✅ **24-hour periods** - Exactly 1 day per period
✅ **No manual period management** - Automatically increments every day
✅ **Timezone independent** - Uses UTC globally
✅ **Simple calculation** - No complex date math required

### **Prize Distribution (in $TRIA):**

```solidity
/**
 * @dev Calculate prize amount for a specific rank
 * @param rank Player's rank (1 = first, 2 = second, 3 = third)
 * @param totalPrizePool Total prize pool in $TRIA
 * @return Prize amount in $TRIA
 */
function calculatePrizeForRank(
    uint256 rank,
    uint256 totalPrizePool
) public pure returns (uint256) {
    if (rank == 1) return (totalPrizePool * 50) / 100;  // 50% to #1
    if (rank == 2) return (totalPrizePool * 30) / 100;  // 30% to #2
    if (rank == 3) return (totalPrizePool * 20) / 100;  // 20% to #3
    return 0;  // Only top 3 get prizes
}

/**
 * @dev Claim prize after period ends
 * @param period Period number to claim prize for
 */
function claimPrize(uint256 period) external nonReentrant {
    require(block.timestamp >= getPeriodEndTime(period), "Period not ended");
    require(!hasClaimed[msg.sender][period], "Already claimed");
    require(scores[msg.sender][period] > 0, "No score found");
    
    uint256 rank = getPlayerRank(msg.sender, period);
    require(rank > 0 && rank <= 3, "Not in top 3");
    
    uint256 totalPrizePool = periodPrizePool[period];
    uint256 prizeAmount = calculatePrizeForRank(rank, totalPrizePool);
    
    hasClaimed[msg.sender][period] = true;
    
    // Transfer $TRIA tokens to winner
    require(triaToken.transfer(msg.sender, prizeAmount), "Transfer failed");
    
    emit PrizeClaimed(msg.sender, period, rank, prizeAmount);
}
```

1. **Reentrancy Protection**: 
   - Use `nonReentrant` modifier on all functions
   - Follow checks-effects-interactions pattern

2. **Slippage Protection**:
   - Implement `amountOutMinimum` in swap
   - Default 0.5% slippage tolerance
   - Revert if swap output too low

3. **Price Oracle**:
   - Use Chainlink price feeds
   - Implement Uniswap V3 TWAP oracle
   - Multi-source price aggregation

   - No approval needed (contract swaps directly)
   - Prize claims use `transfer()` not `transferFrom()`

5. **Emergency Functions**:
   - Admin can pause entries if needed
   - Admin can withdraw stuck tokens
   - Circuit breaker for swap failures

6. **Period Validation**:
   - Ensure period ended before claims
   - Track claims to prevent double-claiming
   - Validate scores exist before claims

## 🎮 Updated Game Flow

### **Player Flow:**

1. **Entry Payment** 💰
   - Player pays variable ETH (e.g., 0.00001, 0.00002, 0.00004 ETH)
   - Contract auto-swaps to $TRIA via Uniswap V3
   - 100% of $TRIA goes to prize pool

2. **Commit Score** 🔐
   - Generate random nonce
   - Commit hash(0, nonce, address) to blockchain
   - Store nonce locally for reveal

3. **Play Game** 🎮
   - Player plays the game
   - Score calculated based on performance
   - Weighted score = base score × (entry amount / 1.0)

4. **Reveal Score** 🔓
   - Submit revealScore(weightedScore, nonce) to blockchain
   - Contract verifies hash matches
   - Score stored on-chain if valid

5. **Claim Prize** 🏆
   - After period ends, check leaderboard
   - Claim $TRIA rewards based on rank
   - Transfer $TRIA to wallet

### **No Time Limits:**
- ⏰ **No deadline** between commit and reveal
- ✅ **Nonce validation** is the only requirement
- 🔒 **Anti-cheat** ensured by pre-game commitment
